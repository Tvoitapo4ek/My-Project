# 3D-модели и анимации для Aetherwright

Короткое руководство: как сделать модель детали, существа или персонажа,
подключить её в игру и анимировать. Инструмент — **Blender** (бесплатный),
формат — **glTF 2.0 Binary (`.glb`)**.

## 1. Как игра подхватывает модели

Каждый объект по умолчанию собран из простых фигур. Если существует файл

```
assets/models/<категория>/<ключ>.glb        (или mods/<мод>/models/…)
```

игра **автоматически** прячет примитивы и показывает модель. Физика при этом
не меняется: столкновения считаются по игровой форме, поэтому модель не может
сломать баланс.

| Категория | Ключ | Пример файла |
|---|---|---|
| `parts` | ключ детали: `engine`, `wheel`, `gear`, `frame`, `smelter`… | `assets/models/parts/engine.glb` |
| `creatures` | `hollowling` | `assets/models/creatures/hollowling.glb` |
| `characters` | `explorer` (персонаж игрока) | `assets/models/characters/explorer.glb` |

## 2. Масштаб, оси, точка опоры

* **1 единица Blender = 1 метр = 1 блок.** Двигатель — куб 1×1×1, колесо —
  диаметр 1.2 м, толщина 0.35, персонаж — рост 1.8 м.
* Экспорт glTF в Blender сам переводит оси (Blender Z-вверх → игра Y-вверх),
  галочку **+Y Up** оставьте включённой.
* **Точка опоры (origin)** — центр игровой формы:
  * детали — центр куба/цилиндра (как у коллайдера);
  * существа — центр тела (сферы радиусом 0.45);
  * персонаж — центр капсулы (0.9 м над ногами).
* «Перёд» объекта смотрит в **−Y в Blender** (= −Z в игре). Колёса и шестерни
  вращаются вокруг **оси Z Blender (вверх)** — игра совмещает её с осью шарнира.
* Примените масштаб и поворот: `Ctrl+A → All Transforms` перед экспортом.

## 3. Стиль (из концепта)

Умеренная стилизация, выразительный силуэт, правдоподобные материалы без
фотореализма. Мало полигонов (деталь 100–2 000 треугольников, существо
1 000–8 000). Материалы — **Principled BSDF** (Base Color, Roughness,
Metallic, Emission — экспортируются в glTF). Светящиеся элементы магии —
через Emission с умеренной силой, чтобы не мешать читаемости.

Текстуры можно запечь в одну картинку 256–1024 px; пиксельный стиль —
интерполяция `Closest` в Blender (в игре она сохранится).

## 4. Скелет и анимации

1. Добавьте арматуру (`Shift+A → Armature`), привяжите меш
   (`Ctrl+P → With Automatic Weights`).
2. Каждая анимация — отдельное **действие (Action)** в Dope Sheet →
   Action Editor. **Имя действия = имя клипа в игре.**
3. Для каждого действия нажмите **Push Down** в NLA-редакторе (или включите
   экспорт всех действий), чтобы оно попало в файл.

Игра просит клипы по имени (если клипа нет — ничего страшного):

| Клип | Когда играется |
|---|---|
| `idle` | стоит на месте |
| `walk` | идёт / бродит |
| `run` | бежит, преследует |
| `attack` | атака |
| `hit` | получил удар |
| `work` | механизм работает (двигатель включён, дробилка крутится) |

Клипы зацикливаются, переход между ними плавный (0.2 с). Частота кадров
анимации — 24 или 30 к/с.

## 5. Экспорт

`File → Export → glTF 2.0`:
* Format: **glTF Binary (.glb)**;
* Include: *Selected Objects* (только модель и арматура), без камер и ламп;
* Transform: **+Y Up**;
* Data → Mesh: *Apply Modifiers*, UVs, Normals; Materials: *Export*;
* Animation: включено, *Actions / NLA tracks*, *Always Sample Animations*.

Сохраните файл по пути из раздела 1 — при следующем появлении объекта
(новая деталь, новое существо, перезапуск) модель будет использована.

## 6. Проверка

* Неверный путь или битый файл — игра пишет предупреждение и оставляет
  примитивы, игра не падает.
* В консоли при загрузке видно `model engine ← models/parts/engine.glb`.
* Если модель «висит» в стороне — проверьте origin (раздел 2).
* Если модель повёрнута — проверьте «+Y Up» и примените трансформации.

## 7. Что дальше

* Иконки предметов из моделей, модели блоков свободной геометрии.
* Анимация устройства-проектора интерфейса (клипы `device_open`,
  `device_close` на модели персонажа).
* Разные модели архетипов (маг, оборотень в двух формах) — тот же механизм:
  `characters/<архетип>.glb`.
