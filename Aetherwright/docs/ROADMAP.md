# Дорожная карта после First Playable

Основано на «Концепции игры v1.0» и разделе 24 (пространственный интерфейс).
Правило работы: **технические / фундаментальные этапы (T)** выполняются без
отдельного согласования; **геймплейные этапы и этапы мира (G)** начинаются
только после явного «да» по конкретному пункту.

## 1. Сверка концепта с текущим прототипом

### Совпадает (ничего менять не нужно)
* Rust + Bevy, модульная архитектура, воксели в чанках, greedy-мешинг.
* Манипулятор вместо кирки, гравизахват с ограничением по массе.
* Сетка по сетке для блоков, свободная установка функциональных деталей.
* Физически основанное движение, 1-е/3-е лицо.
* Инвентарь сеточный, без веса.
* Магия подчиняется инженерным принципам (сбор → накопление → передача → преобразование).
* Режимы выживания и креатива, сохранения с версиями.

### Расходится с концептом — нужно решение (НЕ меняю молча)
| Тема | Сейчас в прототипе | В концепте | Предложение |
|---|---|---|---|
| Смерть | возрождение у точки появления | точка возрождения задаётся игроком (кровать, стенд); на месте смерти — энергетический сгусток с проклятием | этап G: точки возрождения + сгустки |
| Виды магии | спокойная / раздражённая / древняя | + конденсированная, + уникальная магия междумирья | добавлю два вида в **модель данных** (T), без механик |
| Потребности | здоровье, голод, жажда, температура | + кислород, локальные травмы | кислород — вместе с водой/подводным этапом (G) |
| Инвентарь | без сортировки/поиска/фильтров | фильтры, автосортировка, поиск | войдёт в новый пространственный инвентарь (T/UI) |
| Архетипы | один персонаж | маг и оборотень (две формы, разная экипировка) | архитектура интерфейса и экипировки — без привязки к модели (T); сами архетипы — G |
| Мир | один небольшой конечный участок | гибридная огромная конечная структура, острова, подземелья | этап T: стриминг чанков; география — G |
| Мода | статические таблицы в коде | SDK/API, контентные и системные моды | этап T1 (данные в файлах, папка `mods/`) |
| Креатив | время, гравитация, заливка | + погода, редактирование рельефа, отладка центра масс | частично T (отладка), остальное G |

### Открытые вопросы концепта, которые я не трогаю
Не заполняю случайными предположениями: география, история цивилизаций,
спецификация рун, баланс, антагонист, башня, вторая сцена, сюжет.

## 2. Этапы

### T1 — Данные и модификации (делаю сейчас)
* Блоки, текстуры, предметы, рецепты — в файлах `assets/content/*.ron`
  (с комментариями), а не в коде. Встроенные значения — запасной вариант.
* Моды: `mods/<имя>/content/*.ron`, `mods/<имя>/textures/…` — добавляют и
  переопределяют контент; идентификаторы — строковые ключи.
* Текстуры блоков — PNG-файлы (`assets/textures/blocks/*.png`), процедурные
  текстуры — только запасной вариант; горячая перезагрузка.
* Блоки `u16` (до 65 535 типов); сохранения хранят палитру «ключ ↔ номер»,
  поэтому порядок блоков в модах не ломает миры. Миграция сохранений v1 → v2.
* Виды магии: + конденсированная, + уникальная (только данные).

### T2 — Редактор текстур в игре
* Пиксельный редактор: карандаш, ластик, заливка, пипетка, палитра, отмена,
  сетка, предпросмотр на кубе; сохранение в PNG; мир обновляется сразу.
* Документация: `docs/MODDING.md`, `docs/MODELS_AND_ANIMATION.md`
  (Blender → glTF, масштаб, оси, имена анимаций), загрузка `.glb`-моделей
  деталей/существ вместо примитивов, если файл существует.

### T3 — Пространственный голографический интерфейс (раздел 24)
* Устройство персонажа (компонент, не привязан к модели/архетипу),
  анимация активации, панели в 3D-пространстве перед персонажем (UI,
  отрисованный в текстуры на голографических плоскостях), ввод мышью через
  пересечение луча с панелью → единая система событий.
* Состояние: `DeviceState` (закрыто/открывается/открыто/закрывается) +
  `DeviceSection`; медленное движение и обзор разрешены, игровые действия
  блокируются через общее состояние ввода.
* Разделы как плагины (`SectionRegistry`): инвентарь (реальные данные, фильтр,
  сортировка, поиск, панель предмета), экипировка (3D-проекция персонажа,
  слоты), карта (голографический рельеф из реального мира, туман неизведанного,
  метки, вращение/масштаб/сдвиг), журнал (записи открываются сканером),
  чертежи (3D-превью, сохранение/загрузка/копии/версии), настройки,
  персонаж.
* Отдельные инженерные панели механизмов (реальные данные: энергия,
  мощность, нагрузка, скорость, соединения, диагностика).
* Настраиваемый HUD: позиция, размер, прозрачность, видимость, профили.

### T4 — Технический фундамент мира
* Стриминг чанков вокруг игрока, фоновый ремешинг правок, LOD дальних чанков.
* Профилирование (tracy), бенчмарки мешинга/физики.
* Сетевой слой-заготовка: команды (`BlockEdit`, `JointRequest`, …) как
  сериализуемые сообщения с авторитетной стороной.

### G-этапы (только после согласования, по одному)
G1 точки возрождения и сгустки смерти · G2 кислород, вода, подводные
экспедиции · G3 архетипы (маг/оборотень) · G4 логика/сигналы/датчики ·
G5 повреждения и ремонт механизмов · G6 жидкости · G7 погода ·
G8 экосистемы и поведение существ · G9 «Размышление» · G10 аномалии
(гравитационные/временные/пространственные, генераторы, стабилизация) ·
G11 реакция междумирья на героя · G12 вторая сцена и башня · G13 транспорт
(аэродинамика, плавучесть) · G14 огонь.
