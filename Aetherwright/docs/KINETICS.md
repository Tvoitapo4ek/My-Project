# Кинетическая сеть (механическая передача)

Решение согласовано: **гибрид в духе Create / Create Aeronautics**.
Вращение на заводах и в стационарных механизмах — не физика, а граф на сетке;
физика подключается только там, где должны двигаться тела.

## Как это работает

1. **Блоки на сетке** (`kinetics/mod.rs`): приводной вал, зубчатое колесо,
   большое зубчатое колесо, коробка передач, муфта, реверс, ручной привод,
   электромотор, подшипник. Это статичные объекты на клетках — без
   динамических тел и ограничений решателя.
2. **Связи** (`kinetics/network.rs`):
   * вдоль оси — вал к валу, вал к колесу, к коробке: 1 : 1;
   * колёса одной оси бок о бок: −1 (вращение в обратную сторону);
   * малое ↔ большое по диагонали: ×½ / ×2;
   * большое ↔ большое через клетку: −1;
   * коробка передач: передаёт во все шесть сторон, насквозь — с реверсом;
   * муфта разъединена — связи нет; реверс разворачивает одну сторону;
   * машина (дробилка) принимает вращение с любой стороны.
3. **Решатель** — чистая функция: обход графа → относительные скорости;
   источники задают базовую скорость. Источники с разными скоростями —
   **конфликт**, сеть стоит. Предел — 256 об/мин.
4. **Мощность и нагрузка.** Источник даёт мощность в SU. Каждая деталь
   тратит `трение × |об/мин|`, машина — `работа × |об/мин|`. Если нагрузка
   больше мощности, сеть **замедляется** до `мощность / нагрузка`; ниже 20 % —
   **останавливается**.
5. **Прочность.** Передаваемая мощность `min(нагрузка, мощность)`; деталь
   слабее этого **ломается** (выпадает предметом), сеть пересчитывается.
6. **Пересчёт только при изменениях**: поставили/сняли блок, переключили
   муфту, запустили привод, у мотора появилась/кончилась энергия.
7. **Отрисовка**: ротор поворачивается на `обороты × время` — никакой физики,
   тысячи деталей не нагружают решатель.
8. **Граница с физикой — подшипник.** Физическую деталь, присоединённую к
   подшипнику шарниром (гравизахват → «Шарнир»), подшипник вращает мотором
   шарнира с реальным моментом (≈ 4 Н·м на SU). Так появятся мельницы,
   пропеллеры и подвижные сборки; транспорт из физических деталей работает
   как раньше.

## Энергия мотора

Пока нет проводов (этап V2), мотор берёт энергию из заряженной
энергоячейки **вплотную** (до 1,8 м). Расход — пропорционально реально
отданной мощности (`energy_per_su`). Нет энергии — мотор не крутит.

## Управление

* Предмет в руке, ПКМ — поставить; ось — по грани, к которой ставите, или по
  оси блока, к которому пристраиваете (продолжить вал, поставить колесо
  рядом). **R** — принудительная ось X → Y → Z → авто.
* Манипулятор «Добыча», ЛКМ по блоку — забрать.
* «Механизмы»: ручной привод — ЛКМ крутить 4 с; мотор — ЛКМ вкл/выкл,
  ПКМ — обороты 16/32/64/128/256; муфта и реверс — ЛКМ.
* **F6** — оверлей сетей: зелёная — работает, жёлтая — нагрузка > 80 %,
  красная — перегрузка или конфликт, серая — стоит.
* Взгляд на блок — инженерная панель: обороты, мощность и нагрузка сети,
  прочность, диагностика.

## Данные и моды

`assets/content/kinetics.ron` (и `mods/<мод>/content/kinetics.ron`):
`key`, `role`, `impact`, `strength`, `source_rpm`, `source_power`,
`energy_per_su`, `item`. Новый вид детали с существующей ролью — только
данные; новая роль — код в `network.rs`.
