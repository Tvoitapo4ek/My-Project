# Пространственный голографический интерфейс (раздел 24)

Интерфейс персонажа — не меню поверх экрана, а проекция устройства в мире.

## Управление

| Клавиша | Действие |
|---|---|
| Tab | открыть устройство на главной / закрыть |
| I / J / N | открыть сразу инвентарь / журнал / карту (повторное нажатие закрывает) |
| Esc | закрыть устройство (или прекратить ввод текста) |
| ЛКМ | выбор на панелях, перетаскивание проекций (поворот) |
| СКМ-перетаскивание | сдвиг карты |
| Колесо | прокрутка списков, масштаб проекций |
| ПКМ (держать) | осмотреться, не закрывая проекцию |
| WASD | медленный шаг (35% скорости, без бега и прыжка) |

Пока устройство открыто, инструменты, строительство, бой, взаимодействие и
управление техникой не работают: все такие системы требуют
`InputFocus::Gameplay`, а открытое устройство — это `InputFocus::Device`.
Одна команда никогда не достаётся одновременно игре и интерфейсу.

## Как это устроено

```
holo/
  mod.rs        реестр разделов (HoloSections), навигация (HoloNav), BuildSection
  device.rs     HoloDevice (компонент носителя), DeviceState, анимация, клавиши, DeviceCommand
  panels.rs     панели: UI → текстура → полупрозрачная плоскость; луч курсора → указатель
  projection.rs 3D-голограммы: фигура персонажа, ядро, виды (поворот/наклон/масштаб)
  style.rs      визуальный язык: стекло, тонкие линии, голубой/фиолетовый/янтарный
  engineering.rs инженерная панель над механизмом
  sections/     разделы: home, inventory, craft, equipment, map, journal,
                blueprints, character, settings
```

* **Состояние** — `DeviceState` (закрыто → открывается → открыто →
  закрывается) + `DeviceAnim` (0..1). Открыть/закрыть из любого кода:
  `DeviceCommand::Open(Some("map"))`, `DeviceCommand::Close`.
* **Отрисовка** — у каждой панели своя текстура и 2D-камера; в текстуру
  рисуется обычный Bevy UI. Плоскости лежат на слое `HOLO_LAYER`, его рисует
  отдельная камера поверх мира, копирующая основную: проекция не уходит в
  стены, но имеет настоящую перспективу. Каждая плоскость — стекло + рамка
  со светящимися краями (глубина). Проекция стоит перед персонажем, смотрит
  на камеру и лениво догоняет взгляд; в 3-м лице поднимается над головой и
  масштабируется по расстоянию.
* **Ввод** — `drive_pointer` пересекает луч курсора с плоскостями и отдаёт
  Bevy Picking события отдельного указателя (`HOLO_POINTER`): наведение,
  нажатие, перетаскивание, прокрутка работают на 3D-панелях как в обычном UI.
  Тот же путь подходит для геймпада/VR (нужен только другой источник луча) и
  для нескольких игроков (свой указатель на игрока).
* **Данные** — разделы не хранят состояние в UI: состояние — ресурсы
  (`InvUi`, `JournalState`, `MapMarkers` …), картинка строится заново при
  изменении (`HoloNav::rebuild`), часто меняющиеся числа — `LiveText`.
* **Сохранение** — модули сами сохраняют свои данные через `SaveHook`
  (`save::world_save`): экипировка, исследованная карта и метки, журнал.
  Старые сохранения загружаются (нет данных → значения по умолчанию).

## Добавить раздел

```rust
pub struct MySection;
impl Plugin for MySection {
    fn build(&self, app: &mut App) {
        app.init_resource::<HoloSections>();
        app.world_mut().resource_mut::<HoloSections>().register(SectionInfo {
            id: "my", title: "Мой раздел", glyph: "◆", order: 60,
        });
        app.add_systems(Update, build.in_set(HoloSet::Build));
    }
}

fn build(mut msgs: MessageReader<BuildSection>, mut commands: Commands) {
    for m in msgs.read().filter(|m| m.id == "my") {
        commands.entity(m.content).with_children(|p| {
            action_button(p, "Нажми", 14.0, Node::default(), false,
                HoloAction::new(|w| { /* любой код с доступом к World */ }));
        });
        // m.detail — правая панель, m.projection — точка для 3D-голограмм.
    }
}
```

Навигация и кнопка «Главная» появятся сами.

## Другое устройство / архетип

`HoloDevice { name, emitter }` — компонент носителя. Маг или оборотень
получат своё устройство (другое имя, точка излучателя, в будущем — набор
разделов и стиль) без изменений в панелях и разделах.

## Инженерные панели

Наведите взгляд на деталь механизма (до 7 м): над ней появится панель с
реальными данными — энергия сети, заряд, потребление, скорость вращения,
оценка нагрузки, соединения, масса, состояние станции, диагностика
(«нет питания», «перегрузка», «не соединена»…). Целостность покажет система
повреждений (этап G5).

## HUD

Настройки → «Интерфейс (HUD)»: масштаб и прозрачность всего HUD, включение
панелей; справа — для каждой панели сдвиг, размер и непрозрачность. Изменения
видны сразу, «Сохранить настройки» пишет `assets/config/game.json`.

## Честные ограничения прототипа

* Экипировка без характеристик: тестовые предметы проверяют слоты, перенос и
  проекцию. Оружие/инструмент берутся из руки (бой работает как раньше).
* Карта показывает поверхность; подземные уровни — после стриминга мира (T4)
  и решения о вертикальной структуре мира (открытый вопрос концепта).
* Записи журнала — тестовые и описывают только то, что уже есть в игре; лор
  не придуман.
* Окна станций (плавильня, ящик) пока плоские; их перенос в инженерные
  панели — следующий шаг интерфейса.
* Поиск в инвентаре — латиница/кириллица с клавиатуры; IME не поддержан.
