# Журнал разработки

## Окружение
* Rust 1.97.1 (Bevy 0.20.1 тянет `wesl 0.6`, которому нужен ≥1.97.1).
* Bevy **0.20.1**, Avian3d **0.8.0** — точные версии (`=`), `Cargo.lock` в репозитории.
* serde / serde_json — сохранения и конфиг (те же версии, что уже тянет Bevy).
* Разработка велась в Linux-контейнере без GPU: игра запускается под Xvfb
  с Mesa lavapipe (программный Vulkan) — скриншоты и сквозной автотест
  выполняются в реальной игре. Сборка и тесты на macOS — через GitHub Actions
  (`.github/workflows/aetherwright.yml`, раннер `macos-latest` = Apple Silicon).

## Этап 1 — основа проекта ✅
* Модульная структура: `core` (состояния, конфиг, сообщения, часы мира),
  `player` (ввод, движение, камера, модель), `world` (окружение), `ui`
  (HUD, уведомления, отладка), `autotest` (сквозной сценарий).
* Состояния: `AppState` (Loading/InGame), `GameMode` (Survival/Creative),
  `InputFocus` (Gameplay/Inventory/BuildMenu/Paused) — курсор захватывается
  только в Gameplay.
* Физика в фиксированном шаге (60 Гц), интерполяция трансформов всех тел.
* Персонаж — динамическое тело Avian; контроллер в `FixedUpdate`.
* Камера 1-го/3-го лица с обходом препятствий.
* Смена дня и ночи: солнце, цвет неба, туман, ambient.
* `--autotest`: 8 проверок (стоит на земле, ходьба, прыжок, приседание,
  вставание, внешний импульс, камера 3-го лица).

Исправлено в ходе этапа:
* конфликт доступа ECS в `update_crouch` (SpatialQuery читает `Collider`) → `ParamSet`;
* слишком тёмная сцена — `Exposure::SUNLIGHT` не соответствовал освещённости;
* автотест: опрос клавиатуры перезаписывал скриптовый ввод → флаг `scripted`.

## Этап 2 — воксельный мир ✅
* `world/voxel.rs` — таблица из 24 типов блоков (свойства: отрисовка, твёрдость,
  уровень добычи, текстуры граней, дроп, свечение, излучение эфира).
* `world/chunks.rs` — кубические чанки (`chunk_size`³, 1 байт/блок, размер из
  конфига), `VoxelWorld` с API get/set, dirty-набором для перестройки и
  `modified`-набором для сохранений; правка на границе помечает соседей.
* `world/generation.rs` — детерминированная генерация (value-noise fBm):
  холмы, горы, озёрные котловины, пещеры, руды (уголь/железо/медь/древний камень),
  деревья через границы чанков, трава и ягодные кусты, две «точки интереса»:
  шпиль эфирных кристаллов в кольце древних руин и аномалия раздражённой магии.
* `world/meshing.rs` — greedy meshing с AO в ключе слияния; вход — padded-копия
  чанка с бортиком соседей, поэтому мешер чистая функция и работает в пуле потоков.
* Коллайдер чанка — `Collider::voxels` (Avian/parry): точно повторяет блоки и
  не даёт «призрачных» столкновений на внутренних рёбрах.
* Загрузка: генерация и мешинг всех чанков в `AsyncComputeTaskPool`, экран загрузки.
  Правки в игре перестраиваются синхронно с бюджетом чанков на кадр.
* `world/interaction.rs` — DDA-луч по сетке, `BlockEdit` → валидация
  (границы, неразрушимые блоки, пересечение с телами) → `BlockChanged`.
* `world/destruction.rs` — частицы-обломки, растения теряют опору, песок/гравий
  отрываются (`DetachedBlock`, обработка в физике — этап 4).
* `world/materials.rs` — процедурные текстуры 16×16 для всех материалов.
* Персонаж: плавание (доля погружения по 3 точкам), выбор спавна на ровной
  открытой площадке.

Исправлено: в мире не было озёр (добавлены котловины + тест на 3 сидах);
спавн под деревом ломал проверки движения; неверный порог в тесте соседнего чанка.

## Этап 3 — инструменты и инвентарь ✅
* `items/` — статическая таблица из 43 предметов (ключ, имя, категория, стопка,
  способ использования, масса, цвет, описание). Сохранения ссылаются на ключи,
  не на индексы. Данные предметов не связаны с UI.
* `items/inventory.rs` — сетка 36 ячеек (первые 9 — хотбар): стопки, добавление
  с переполнением, удаление «всё или ничего», клики как в классических
  инвентарях (взять/положить/поменять, половина, по одному, Shift — переложить).
* `items/drops.rs` — выпавшие предметы — физические тела (слой Item); автоподбор
  обычных ресурсов с «магнитом» (P — вкл/выкл), ручной подбор E, выброс G.
* `core/rules.rs` — `ModeRules`: различия выживания и креатива как данные,
  выставляются при смене `GameMode` (M).
* `tools/` — `ActiveTool` из выбранного слота; манипулятор с режимами
  Добыча / Сканирование / Резка / Механизмы (Q); удержание ЛКМ с прогрессом,
  зависящим от твёрдости и уровня бура; модули (бурение II, резка) ставятся ПКМ;
  размещение блоков ПКМ (предмет списывается только после реального изменения
  мира); сканер (`Scannable` для сущностей, расширения через `ScanExtras`);
  модель прибора от первого лица, цвет ядра = режим.
* UI: модульный HUD (`HudPanel` + `HudConfig`, F1 скрыть всё), хотбар, строка
  инструмента, цель под прицелом с прогрессом добычи, панель сканера;
  экран инвентаря (I/Tab) с подсказками, каталог всех предметов в креативе.
* Шрифт JetBrains Mono встроен в бинарник (стандартный шрифт Bevy без кириллицы).

Найдено автотестом и исправлено: резка без модуля работала при удержании кнопки;
слабый магнит автоподбора не вытаскивал предмет из ямы.
