# Устройство игры: анализ, производительность, задел на будущее

## Как устроено сейчас

* **Сетки.** Мир — одна `VoxelGrid` (чанки 16³), каждая физическая
  машина — своя `VoxelGrid` со своим `Transform` и одним `RigidBody`.
  Мешер, коллайдеры, луч, механизмы — общие для всех сеток, поэтому
  машина в блоках и в физике ведёт себя одинаково.
* **Блоки-сущности.** У каждого механизма — сущность-ребёнок сетки
  (`BlockEntity` + `Params` + состояние модулей: `Spin`, `FluidStore`,
  `Engine`, `LogicState`…). Синхронизируется с клетками сама
  (`sync_block_entities`). Переезд между сетками (`assembly`) переносит
  сущность целиком — со всем состоянием.
* **Индекс по видам.** `VoxelGrid::by_mech` — клетки по виду механизма,
  поддерживается в `set`. Системы обходят только свои блоки
  (`entities_of(&FLUID_MECHS)`), а не все сущности сетки.
* **Модули — плагины**, общаются через компоненты и сообщения (`UseBlock`,
  `Toast`, `Sfx`). Порядок — наборы систем (`SignalSet` → `LogicSystems`
  → `MechSet` → жидкости и телеметрия).
* **Данные** — `assets/content/*.ron`: блоки, инструменты, категории,
  описания. Новый строительный блок не требует кода.

## Производительность

Замер — этап `AUTOTEST_ONLY=perf` (с `SANDBOX_PROFILE_SINGLE=1` — в один
поток, точные цифры по разделам): пустой полигон, потом 16 линий по 30
механизмов (496 блоков-сущностей). Отладочная сборка, программный
рендер; в релизе всё в несколько раз быстрее, важны соотношения.

| | до | после |
|---|---|---|
| Шагов физики за медленный кадр | 16 | ≤ 6 |
| Сущностей / мешей (496 механизмов) | 7428 / 5281 | 4298 / 2151 |
| Механика (кинетическая сеть) | 1,63 мс | 0,52 мс |
| Жидкости без единой трубы | 1,9 мс* | ~0 |
| CPU кадра с машинами | 27,6 мс | 17,4 мс |

\* до перехода на точные замеры часть цифр была шумом параллельных систем.

**Что исправлено**
1. **Спираль физики.** Медленный кадр догонял время до 16 шагами физики
   (по 6 подшагов) — и следующий кадр становился ещё медленнее. Теперь
   догоняет не больше 100 мс (≈ 6 шагов): на слабом железе игра
   замедляется, а не «умирает».
2. **Модели механизмов** были по брусочку на сущность (≈ 10 на блок).
   Теперь бруски одного слоя и материала сливаются в один меш, общий для
   всех одинаковых блоков (кеш по содержимому) — в 2,5 раза меньше
   сущностей, меньше вызовов отрисовки и извлечения в рендер.
3. **Кинетическая сеть** пересчитывалась каждый кадр. Теперь у входов
   сети есть «отпечаток» (клетки, роли, источники, переключатели,
   нагрузки); пока он тот же — решение берётся из кеша.
4. **Жидкости и логика** обходили все блоки-сущности сетки, теперь —
   только свои (индекс `by_mech`).
5. **Профайлер** (`src/profile.rs`): `let _t = profile::scope("имя")` в
   системе; цифры — в меню F3.

**Что ещё стоит сделать, когда понадобится**
* Плавучесть и ленты вызывают `grid.cells()` — полный обход всех клеток
  тела с выделением памяти каждый шаг. Для больших кораблей — кешировать
  список клеток (и «нижние» клетки для лент) по версии сетки.
* Решатель сети — полный обход при любом изменении. Для заводов на тысячи
  блоков — разбить на компоненты и пересчитывать только изменившуюся.
* Чанки мира — одним коллайдером-компаундом на чанк (уже так); для
  генерации мира — выгружать дальние чанки (коллайдеры и меши).

## Задел на будущее

| Что | Что уже есть | Что понадобится |
|---|---|---|
| **Подлодки** | плавучесть по блокам, балласт, вес жидкости, сопротивление воды | давление по глубине (урон/протечки), винт (сила по оборотам, как колесо), рули — сила на блок, как в `buoyancy` |
| **Летательные аппараты** | тело = сетка, силы прикладываются к точкам блоков | блоки «крыло» (подъёмная сила ∝ v², угол атаки), пропеллер/турбина от кинетической сети; плотность воздуха — функция высоты |
| **Давление воздуха и воды** | индекс клеток, сетки в чанках | заливка объёма (замкнутые отсеки корпуса), отсек → давление, протечка через открытые клетки; хранить на сетке, пересчитывать при изменении |
| **Генерация мира** | мир — чанки, сохранение по чанкам (`save`), тип мира в сохранении (`generator`) | генератор по чанкам с seed, подгрузка/выгрузка чанков вокруг игрока, сохранение регионов |
| **Выживание** | инвентарь со стаками и слотами, хранилища, урон-ориентированные действия (монтировка бьёт тела) | прочность блоков, выпадающие предметы-тела, крафт по данным (`recipes.ron`), здоровье/голод — компоненты игрока |
| **Локальный мультиплеер** | состояние в компонентах, ввод через ресурс `MoveInput`, сообщения для действий | ввод — компонент на каждого игрока; сервер-авторитет (физика только там), репликация компонентов (bevy_replicon / lightyear); сохранение уже сериализует всё состояние — тот же формат годится для начальной синхронизации |

**Правила, которые держат этот задел**
* Всё состояние блока — в компонентах его сущности, ничего в `Local` и
  глобальных ресурсах (кроме кешей). Тогда его можно сохранить, перенести
  в другую сетку и передать по сети.
* Новый модуль с состоянием регистрирует его в сохранении
  (`save::SaveHooks`) — одна функция «записать» и одна «прочитать».
* Действия игрока — сообщения (`UseBlock`, клики), а не прямые изменения
  из системы ввода: позже их можно присылать от другого игрока.
* Физика — только в `FixedUpdate`; визуальное сглаживание — отдельно.
